# fsrs-core

FSRS-6 记忆模型的纯 Java 实现。零框架依赖、零 IO、无可变状态，可以同时被 Web 请求、批量优化器和单元测试调用。

```java
FsrsScheduler scheduler = FsrsScheduler.withDefaults();

// 首次复习：传 null 作为上一次的记忆状态
ScheduleOutcome first = scheduler.apply(null, Rating.GOOD, 0);
// -> stability 2.3065, intervalDays 2

// 之后每次复习带上距上次的天数
ScheduleOutcome next = scheduler.apply(first.next(), Rating.GOOD, 2);
// -> stability 10.90, intervalDays 11
```

## 一、模型在算什么

记忆状态由三个量描述，其中只有两个需要存储：

| 符号 | 含义 | 范围 |
|---|---|---|
| **R** | Retrievability，此刻还能回忆起来的概率 | 0 ~ 1（由 S 和时间推出，不存） |
| **S** | Stability，R 降到 90% 所需的天数 | > 0 |
| **D** | Difficulty，这张卡对你有多难 | 1 ~ 10 |
| **G** | 评分：1=Again 2=Hard 3=Good 4=Easy | 1 ~ 4 |

S 的定义是整个模型的锚点：**S 就是"你还有 90% 把握记得住"的那个时间点**。所以记忆曲线不需要拟合，它由等式 `R(S, S) = 0.9` 反推出来。

## 二、七个公式

`w0..w20` 是 21 个可训练权重，默认值取自官方 FSRS-6 规格。

**1. 遗忘曲线**（FSRS-6 的衰减指数本身可训练）

```
R(t, S) = (1 + factor · t / S) ^ (-w20)
factor  = 0.9 ^ (-1 / w20) - 1        // 这个取值保证 R(S, S) = 0.9
```

**2. 首次评分的初始状态**

```
S0(G) = w[G-1]
D0(G) = w4 - e^(w5 · (G-1)) + 1
```

**3. 难度更新**（线性阻尼 + 均值回归，防 "ease hell"）

```
ΔD(G) = -w6 · (G - 3)
D'    = D + ΔD · (10 - D) / 9
D''   = w7 · D0(4) + (1 - w7) · D'
```

**4. 成功回忆后的稳定性**

```
S' = S · ( e^w8 · (11 - D) · S^(-w9) · (e^(w10 · (1-R)) - 1)
           · w15[G=2] · w16[G=4]  +  1 )
```

这条公式里有三个直接可讲的性质：

- D 越大（越难）→ 增益越小
- S 越大（越熟）→ 增益越小，收敛到上限
- **R 越小（拖得越久才复习）→ 增益越大**，这就是间隔效应

**5. 遗忘后的稳定性**（一次 lapse）

```
longTerm  = w11 · D^(-w12) · ((S + 1)^w13 - 1) · e^(w14 · (1-R))
shortTerm = S / e^(w17 · w18)
S'        = min(longTerm, shortTerm)
```

**6. 按目标保持率反解下次间隔**

```
I(r, S) = S / factor · (r ^ (-1 / w20) - 1)      // I(0.9, S) = S
```

**7. FSRS-6 同日复习的稳定性更新**

```
S' = S · e^(w17 · (G - 3 + w18)) · S^(-w19)
```

增益随 S 衰减，所以**同一天反复刷不能让稳定性无限膨胀**。

## 三、两个容易踩的语义

### 遗忘曲线是连续的，调度是整天的

`retrievability(t, S)` 是连续函数——前端画遗忘曲线、优化器拟合参数都需要它。

但**调度按整天算**：0.9 天后复习算"同一天"（走公式 7），1.9 天后复习按 1 天算。这个区别是刻意的，也和官方参考实现一致（它用 `(int) ChronoUnit.DAYS.between(...)` 截断）。

### 稳定性有下限，且并非所有"成功"都能涨

- `STABILITY_MIN = 0.001`，稳定性不会低于它。
- 同日复习"不得下降"的地板**只对 Good 和 Easy 生效**。同一天给 Hard 是允许把稳定性压低的——这一点是实测对拍出来的，不是猜的。

## 四、对拍验证（这个模块最有价值的部分）

`FsrsDifferentialTest` 把本实现与官方 [`io.github.open-spaced-repetition:fsrs`](https://github.com/open-spaced-repetition/java-fsrs) 库逐值比对。关键设计：**两边使用同一份权重数组**——数组是从参考库读回来的 (`reference.getParameters()`)，而不是硬编码，所以"两边默认参数不同"永远不会掩盖"公式不同"。

| 对拍项 | 覆盖范围 | 容差 | 结果 |

| 权重数组 | 21 个参数 | — | 一致 |
| 遗忘曲线因子 | factor | 1e-12 | 一致 |
| 遗忘曲线 | 5 组 S × 6 个整天 | 1e-9 | 一致 |

| **状态转换** | **4 S × 3 D × 5 天 × 4 评分 = 240 组，每组比 stability / difficulty / interval 三个量** | 1e-9 | **一致** |
| 首次复习 | 4 种评分（状态 + 间隔） | 1e-9 | 一致 |

### 对拍抓出的三个真实 bug

靠自己读公式实现，很容易在这三处写错。它们全部是对拍发现的：

| # | 官方实现 | 我最初的实现 | 后果 |
|---|---|---|---|
| 1 | `S' = min(longTerm, S / e^(w17·w18))` | 只有 `longTerm` | S=1、t=10 时算出 0.9006，正确值是 0.7779 |
| 2 | 同日地板只对 Good/Easy | 对所有成功评分 | 同日 Hard 会被错误地"保护"住 |
| 3 | `STABILITY_MIN = 0.001` | 用 `1e-9` | 极端情况下数值行为不同 |

第 1 条的验证很直接：`1 / e^(0.7536 × 0.3332) = 1 / 1.28541 = 0.77796`，与官方输出 0.7779 吻合。

### 刻意不做的部分

- **fuzzing**：官方用三个区间分档 + 固定种子随机数；本实现用统一的 ±5%。fuzzing 是调度体验优化，不属于记忆模型，因此被排除在对拍范围之外（并在代码里注明）。
- **学习步骤状态机**（LEARNING / RELEARNING 的分钟级步骤）：属于服务层关注点，不放在纯算法模块。

官方规格（上表）与 `java-fsrs` README 里给出的默认值略有差异（后者是 `0.2172, 1.1771, ...`，末尾 w20=0.2）。两套都保留在 `FsrsParams` 中：`DEFAULT_FSRS_6` 与 `JAVA_FSRS_DEFAULTS`。对本实现而言二者都正确，因为对拍测试显式传入同一份数组；差异只影响"开箱手感"，不影响公式。
